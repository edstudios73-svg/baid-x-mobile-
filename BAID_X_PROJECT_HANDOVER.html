What BAID X is

BAID X is trust infrastructure for Africa’s workforce, built by BAID X under Baiden Studios. The app connects workers, employers, businesses, project managers, and companies through profiles, work, projects, marketplace listings, messages, reviews, and verification. A subscription is not verification.

The local package description is “BAID X trust infrastructure for Africa’s workforce.” The positioning in code is: “The future of work in Africa isn’t about connections — it’s about capability.” Ghana is the first market, but prices and country behavior are intended to come from backend configuration.

Roadmap

Phases 1–14 are represented by the current repository. They are not all functionally complete. Phase 15 is the next safe phase.

Phase 15 — Stabilization and device QA

Rerun analyzer and the full test suite. Build and install a debug APK on the OPPO CPH2201. Capture all five role homes and the redesigned flows. Fix overflow, keyboard, scrolling, and empty/error states found on device. Test dark mode. Do not mark this complete until the phone actually shows the app.

Phase 16 — Authentication

Test registration, email confirmation, session restore, password reset, deep links, and error states. Google OAuth is not in the client; treat it as new work, not a small bugfix, unless Supabase is later shown to have it enabled.

Phase 17 — Roles and data integrity

Fix worker profile loading before any other profile polish. Separate PM tasks and reports from the project list. Retest company access approval and rejection. Prove Business cannot hire and Employer is not treated as Business.

Phase 18 — Messaging and notifications

Test conversations and realtime. Decide where Messages belongs in navigation. Keep push notifications out until a real provider and token design exist.

Phase 19 — Verification and billing

Complete reviewer authorization. Validate Paystack test checkout, webhook, duplicate events, and subscription state. Do not enable live payments without explicit authorization.

Phase 20 — Security regression

Retest jobs RLS, applications, listings, projects, messages, company membership, profiles, and subscriptions. Do not disable RLS to make a test pass.

Phase 21 — Release readiness

Confirm signing without printing secrets. Produce a real release artifact only after debug QA. iOS, store listing, and production Supabase checks remain open. The app is not ready for publication.

Before flashing Windows

GitHub currently contains the committed source at 321ede4. Cloning GitHub is not enough, because ignored secrets and the keystore are not in Git.

Flutter SDK, Android SDK, Cursor, and local build folders can be reinstalled. They are large and do not need to be copied unless you want to save time. Do not copy build/ as a substitute for source.

Windows 11 recovery sequence

  1. Install Git, Flutter 3.47.4 stable, Dart 3.13.3, Android Studio or the Android command-line tools, platform-tools, and a browser.
  2. Install Claude Code and sign in. Also install GitHub authentication.
  3. Clone https://github.com/edstudios73-svg/baid-x-mobile-.git or copy the backed-up project folder. Open that existing directory. Do not run flutter create.
  4. Check main, origin, and commit 321ede4. If the remote has newer commits, inspect them. Do not force-push.
  5. Restore .env and android/key.properties. Put the keystore where storeFile expects it. Do not commit either file.
  6. Run flutter pub get, flutter doctor -v, flutter analyze, and flutter test.
  7. Reconnect the OPPO phone, enable USB debugging, and accept the computer authorization. Verify with the SDK adb.exe.
  8. Sign in again to GitHub, Supabase, Figma, Claude Code, and Paystack. Confirm the Supabase ref is still vxixalejbnvqivaytxzt before running migrations.

Business model

The billing migration defines plan tiers access, pro, premium, and enterprise. Payment purposes include subscription, verification, boost, promotion, XID, and protected-payment fee. Prices are intended to come from server plan rows. No current price was verified from the live database, and no price should be hardcoded as truth.

Verification is a separate pending/verified/rejected record. Buying verification is documented to create a pending row, not a verified badge. Client payment return does not activate a subscription. Live payments are not active.

UI direction

The implemented Flutter theme is mobile-first, ink, yellow, orange, and blue, with light and dark palettes. Shared widgets hold buttons, lists, badges, headers, search, forms, and page layout. The product direction avoids decorative gradients, glow, and crowded cards. Figma may still differ, including the reported black selected Home pill. Device screenshots are still required before calling the redesign visually accepted.
